1. Architectural Overview & Problem Formulation

Modern computing is dominated by the Memory Wall and the Data Movement Bottleneck. In conventional von Neumann architectures, all data must be shuttled over power-hungry, high-latency off-chip interconnects (such as PCIe or CXL) to the CPU/GPU, even when operations perform very few arithmetic calculations per byte.

Core Thesis: A memory-centric computing architecture must dynamically decide where computation takes place—placing data-intensive, low-reuse tasks directly into 3D-stacked memory logic dies (PIM), while routing compute-intensive, highly reusable kernels to high-performance conventional host cores.

2. Mathematical Placement Formulation & Online Cost Model

For each computational chunk $C$, the runtime decision engine evaluates the operational intensity $I_{op} = \frac{\text{FLOPs}}{\text{Bytes}}$, data reuse factor $\rho_{reuse}$, access pattern $P_{access}$, and current data residency $\text{Loc}$:

$$\text{Cost}_{Host} = T_{xfer}(N_{bytes}, \text{BW}_{CXL}) + T_{compute}(N_{flops}, \text{Peak}_{Host}) + T_{cache\_miss}(\rho_{reuse}, P_{access})$$ $$\text{Cost}_{PIM} = T_{bank\_lat} + \max\left(\frac{N_{flops}}{\text{Peak}_{PIM}}, \frac{N_{bytes}}{\text{BW}_{TSV}}\right) + T_{sync}$$

Dynamic dispatch selects $\arg\min(\text{EDP}_{Host}, \text{EDP}_{PIM})$ with a hysteresis margin $\theta = 1.15$ to prevent switching oscillation. Microarchitectural overhead is explicitly accounted for: $T_{decision} = 250 \text{ cycles} \approx 69.4 \text{ ns}$ and $E_{decision} = 850 \text{ pJ}$.

4. Hardware Feasibility and Overheads

Dynamic placement is realized via a lightweight hardware scheduler in the Host Memory Controller / CXL Root Complex:

  • Decision Latency: 250 clock cycles (~69.4 ns @ 3.6 GHz), representing < 0.5% of total task runtime in real-world workloads.
  • Energy Overhead: 850 pJ per evaluation (< 0.05% of workload energy).
  • Coherence & Consistency: Coarse-grained chunk-level barrier and flit-based invalidations keep caches coherent without hardware complexity.
